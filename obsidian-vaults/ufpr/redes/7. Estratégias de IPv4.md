# Proxy ARP
- Necessidade de usar mais de uma rede
- Evitar o uso de dois NET-IDs para a mesma organização
- Evitar explosão de entradas na tabela IP dos roteadores
- **Proxy é o intermediário** entre a origem e o destino
- **Invés de passar o endereço físico da origem, passa da proxy ARP**
	- Proxy ARP encaminha e recebe todos os quadros de uma rede
	- Mantém a tabela com todos os endereços das redes
- Camada de ENLACE
# SubRedes
- Camada de Rede (pacotes IP)
- Mais de uma rede física
- Roteadores internos a organização
- Usada atualmente![[subrede.png]]
- Empresta BITs do host-id para endereçar redes internas
- **Máscara de sub-rede**
	- Bit 1 - NET-ID
	- Bit 0 - HOST-ID
	- Mesmo tamanho do endereço IP
### Descobrindo e validando subredes
IP: 192.39.100.86
Mascará: 255.255.255.192
1. Descobrir a classe (C)
2. Ver os bits do HOST-ID da mascará
3. Ver quais o host real e a subrede
	1. No exemplo será a subrede 01 de host 22
4. Definir o host:
	1. Host: 22 da Subrede 192.39.100.64 (sem o host-id real)
# CIDR (classless Inter-Domain Routing)
Medo de acabar os net-ids classe B
Movimento para aumentar o espaço de endereçamento
- Racionalizar a atribuição de endereços e roteamento hierárquico
- Acabar com as classes e otimizar a alocação da classe C sobrando

Flexibilizar a fronteira de NET-ID e HOST-ID
- net-id CIDR vão de 13 a 27 bits
- host-id CIDR vão de 5 a 19 bits

Prefixo CIDR
- Definir quantidade bits de net-id
- *200.17.212.179/25*

Blocos maiores para autoridades que passam blocos para provedores, organizações...
Hierarárquia inicia nos continentes
![[cidr-continentes.png]]
Os prefixos CIDR definem quantos bits precisa-se olhar para ver o net-id e definir o próximo passo
