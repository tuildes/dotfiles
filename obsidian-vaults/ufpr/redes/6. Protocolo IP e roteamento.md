# Protocolo RARP
- Dado endereço físico, descobre o endereço IP
- Utilizado quando não é possível ter uma memória secundária (disco)
	- Máquinas **diskless**
- Requisição em broadcast
- Respondido por servidor RARP
- Feito na inicialização (boot) da máquina
# Protocolo IP
- 3° camada - REDE (roteamento)
- Encaminhamento de datagrama
- **Não confiável**
	- Não da para saber se o pacote IP chegou
	- Se perder, nada é avisado
- **Não orientado à conexão**
	- Não tem ordem -> embaralhados no destino
	- O roteamento é feito individualmente
	- Caminhos diferentes
- Vantagens desses "problemas"
	- Roteamento mais leve e simplificado
	- Faz confiabilidade nas pontas (hosts)
- Quem faz a confiabilidade do IP
	- Camada de transporte - TCP
		- Confiável e orientado à conexão
	- Protocolo de aplicação
- **Datagramas**
	- Pacotes de protocolos não confiáveis e não orientados
### Roteamento do IP
- Feito usando NET-ID quase todo caminho
	- O HOST apenas na rede do destino
- Tipos de roteamento:
#### Tipo 01 - DIRETO
1. Origem e destino no mesmo host
2. **Comunicação de processos locais**
3. Nem vai para a rede (placa)
#### Tipo 02 - DIRETO
1. NET-ID iguais e HOST-ID diferentes
2. Mesma rede local (LAN)
3. Antes de comunicar o IP, chama o ARP
#### Tipo 03 - INDIRETO
1. NET-ID diferentes
2. Nos roteadores tem uma tabela de roteamento para os NET-ID
	1. TABELA IP (próximo passo) - (NET-ID destino, prox-passo)![[prox-passoNETID.png]]
	2. Cada roteador so define o próximo passo para um NET-ID
	3. Decisão independente
		1. Ou seja, de A->B pode ser diferente de B->A
	4. *As tabelas são preenchidas por protocolos de roteamento...*
##### Problemas: LOOP
Pode acontecer de ter LOOP
Um roteador joga para o outro fazendo um ciclo
