**Camada de transporte**: HARDWARE (processos)
**Dificuldade**: descobrir qual processo pediu o protocolo
- IP apenas identifica o host
## Porta (port)
Número de 16 bits (2 bytes)
- Identificar o processo que se comunica
- Portas únicas para o TCP e UDP
- Par (Endereço IP e PORTA)

**Reservado**
0 .. 1023 -> IANA (protocolos padronizados)
## Protocolo UDP
User Datagram Protocol

Para processos se comunicarem entre si
- Serviço não confiável e não orientado a conexão
- Pacote: SEGMENTO![[datagramaUDP.png]]
- CheckSum opcional
	- o IP só calcula do header
- Utiliza-se o ICMP para reportar alguns erros (como PORTA)
## Protocolo TCP
Transmission Control Protocol
- Confiável e orientado à conexão
	- Confirma que vai chegar e vai ser ordem
- UDP é muito simples para utilizar
- TCP faz muita coisa:
	- Resolve pacotes perdidos
	- Ordem
	- Fluxo
	- Congestionamento...

- Transmissão confiável e ordenado
- Comunicação em circuito virtual
- Diversos controles
- Comunicação full-duplex
- Faz o controle de fluxo: taxa correta para ambas as máquinas suportarem
	- ACK
### Casos que TCP não é usado
Use sempre, exceto em:
1. Aplicação de tempo real com TCP não cumprido: VoIP
2. Multicast: não é possível controlar todo o grupo
3. Aplicação de gerência de falhas e desempenho da rede: para ver a taxa de erros, etc.
4. Desempenho extremo
